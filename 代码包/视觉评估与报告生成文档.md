## 当前有效依赖

主配置使用 Qwen3.5-0.8B / 224 输入 / llama.cpp 0.1.7 / spacemit-ort 2.0.6。
提示词与响应 schema 唯一正式目录为 `configs/risk_assessment_v1_08b/`。
旧 2B/384 对照、YOLO 训练/检测、候选提示词/数据集评分脚本已归档，不参与正式风险输出。

旧 `run_board_study.py` 的模型服务与请求函数提取为主程序 `app/vlm_runtime.py`；
已移除实验调度入口、候选运行时排名和并行模型下载观察分支。
旧 `analyze_risk_degree.py` 的 `parse_coarse`/`overall_level` 提取为 `app/risk_degree.py`；
没有携带读旧数据集/报告路径的实验 main。

## 分析数据流

1. `ready_views()` 核对轮次内路径、编号和图片 SHA256。
2. Pillow 纠正 EXIF 方向、转换 RGB，最长边缩至 1600；记录画质代理值。
3. 为每张构造含系统提示、图片、文本和 schema 的请求，写 `jobs.json`。
4. `vlm_runtime.run_phase()` 核验模型身份，复用常驻服务；否则只启动/停止自己拥有的子进程。
5. 每次保存原始 API 返回、图片摘要、耗时与资源观察。
6. `parse_coarse()` 接受合法 assessed/low|medium|high；失败、非法 JSON、unassessable 不算低。
7. `overall_level()` 取有效照片最高等级，不平均抵消局部高等级。
8. `summarize()` 输出逐图结果与最多三个重点候选，不证明跨图是不同物体。

`coverage_complete` 保持 false；`status=complete` 仅表示输入照片均获得有效评估，不能解读为全屋覆盖。

## 输出文件

| 文件 | 内容 |
|---|---|
| meta.json | 拍照来源、raw/正式图、姿态命令值、事件 |
| READY.json | 完整输入清单及图片摘要 |
| analysis_*/ | jobs、模型原文、runner 日志、模型运行信息 |
| analysis.json | 结构化模型粗评、状态、等级、候选区域 |
| report.md | 机器文字报告 |
| polish/ | 可选措辞槽位、事实摘要、润色元数据 |
| report.html | 内嵌图片的自包含展示报告 |

## 润色与 HTML

报告工具归 PC 模块；同一份工具也能部署到 K1 直接生成 HTML。
冻结事实来自 analysis/meta；`build_packet` 生成 facts 与 SHA256。
`compose/template/run` 将 HTML 使用的 summary/advice 槽位统一写入 `model_output.json`。
`run` 另存模型原始回复为 `model_response.txt`。重新生成模板会替换旧模型槽位。

摘要提及的等级只允许整体等级；第 i 条建议只能使用第 i 个区域的等级。
HTML 在渲染前核对当前事实摘要并再次检查措辞，拒绝部分完成写成完整完成。
这类文本检查不能验证视觉事实，也不能穷尽自然语言中所有暗示；对外报告仍需人工复核。
模型没有提供有效定位时不生成虚构问题卡片，保留逐张评估说明。

## 复现示例（组装目录）

```bash
python app/polish_packet.py build <round_dir> <round_dir>/polish
python app/polish_report.py template <round_dir>/polish
python app/buyer_report.py <round_dir>
```

对应测试：主程序的 risk_degree/room_review/photo_pipeline；PC 模块的 buyer_report/polish_* 和跨模块回归。
测试合成输入和协议，不构成风险准确率或泛化能力验证。
