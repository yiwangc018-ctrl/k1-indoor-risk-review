# 云台控制开发文档

## 当前路线与文件归属

四角度编排唯一入口为本模块 `app/gimbal_flow30.py`，它调用主程序的采图与分析接口。
`gimbal/i2c.py` 为 Linux ioctl I2C 读写；`gimbal/pca9685.py` 仅供显式恢复和离线自检。
`gimbal/__main__.py` 仅提供 `read` 和 `selftest`。
旧 `Hardware/Gimbal/run_scan`、任意角度语音控制、MPU 闭环与试摆入口已移入历史归档。

## 有效硬件配置

唯一有效硬件配置为 `gimbal/config.json`，四角度编排从中读取参数；不能再用旧扫描配置。

| 项 | 当前参数 |
|---|---|
| PCA9685 | i2c-4 / 0x40 / 50Hz |
| pan | CH15，初始 512.7µs |
| tilt | CH11，初始 2055.7µs |
| tilt 上移目标 | 2240.7µs，最大 2241.2µs |
| pan 四个目标 | 994.4 / 1488.9 / 1983.3 / 2477.8µs |
| pan 脉宽限制 | 500–2478µs |
| 相机旋转 | 默认 0；现场确认倒装才用 `--rotate 180` |

角度是由脉宽映射的命令值，不是实测绝对角；正式链路不依赖 MPU6050。
配置随组装生成目录进入部署，板端独立包的配置路径由主配置 `gimbal.config` 指定。
`PcaPulseBus` 不初始化 PCA，不清零其他通道；按配置仅操作 CH15/CH11。

## 时序与异常

初始不拍→tilt 上移→四个 pan 点依次移动/稳定/拍一张→双轴返回。
默认每段移动 2.9s、稳定 0.2s、点位停留 2s、双轴返回 5.2s。
捕获耗时超过停留预算时不会强行截断相机命令，因此不是硬实时 30 秒保证。

起始姿态偏离期望超过 50µs 会拒绝移动。相机锁覆盖起始读取与所有写电机操作。
成功/异常均尝试在锁内返回，再关闭 I2C；采集失败保留已拍证据，不发布 READY。
未取得锁时不做“返回”动作，避免干扰持锁轮次。

## 运维

在组装目录/板端运行：

```bash
python3 app/gimbal_flow30.py read
python3 app/gimbal_flow30.py run --dry-run
python3 -m gimbal selftest
```

前两项只读硬件；selftest 用假 I2C，不接硬件。显式恢复：

```bash
python3 scripts/board/restore_gimbal_initial.py
```

恢复脚本使用 PCA9685 初始化，会清零输出并重新施加 PWM，只在重启/卸力后人工托住相机时执行。
正式四角拍摄不调用这个初始化器，菜单中恢复和采集分开。行程/安装/供电变化后先重新标定。

## 测试

`test_gimbal_flow30.py` 使用假电机和图像验证四张、旋转、初始拒绝和失败返回。
`test_pca_driver.py` 是独立离线脚本，组装器会显式运行，避免被 unittest 漏收。
跨模块锁回归验证相机忙时零电机访问、成功/异常返回前不释放锁。
没有实机验证前，不宣称整理后舵机定位精度、覆盖或长期可靠性已验收。
